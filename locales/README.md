# Sono-Renderer application translations

All application-interface translations live in this directory. Do not put
engine data, LevelData, projects, user subtitles, creative text, command IDs,
or other application state here.

## Structure

- `registry.json` is the single locale metadata registry. It defines stable
  locale IDs, native names, fallback, direction, release/developer audience,
  and translation review status.
- `<locale>/messages.json` maps stable application message IDs to complete
  message templates. `en/messages.json` is the canonical key set and English
  fallback.
- `test/pseudo/messages.json` and `test/rtl/messages.json` are developer-only
  test-locale resources. Their visible text is generated by the localization
  test facility, not advertised as human languages.

The build embeds catalogs discovered under this directory and the Windows
packager also includes this directory as a translator-editable resource
copy. The embedded catalog lets the executable run without a repository path
or working-directory assumption.

## Adding or editing a locale

1. Add a locale metadata entry to `registry.json` with an IETF-style stable
   identifier, native name, fallback, direction, audience, catalog status,
   and review status.
2. Add `<id>/messages.json` using the English catalog's stable keys. Keep
   `zh-CN` and `zh-TW` independently authored. Use `pt-BR` for Brazilian
   Portuguese.
3. Preserve placeholders exactly, including their names and types. For
   example, `{count}` is a runtime value; translate the surrounding sentence
   and reorder the placeholder as the language requires.
4. Use `scripts/validate-locales.ps1` to check JSON, fallback cycles, required
   IDs, missing/unknown message IDs, and placeholder parity. Run the Rust
   localization tests as well; the runtime catalog parser rejects duplicate
   message IDs that JSON object parsers might otherwise overwrite.
5. Run `cargo test --lib localization::tests` and launch the application with
   that locale selected in Settings or from the Home language selector.
6. Add translator context in `locales/contexts.json` when an ID is ambiguous.
   Keys must explain the control or workflow, not just repeat the source
   sentence.

The catalog currently covers foundational navigation and entry-workflow
strings; it does not yet cover all GUI text. Until broader extraction is
complete, untranslated interface strings may remain in English through the
fallback path. A complete catalog key set is not proof of complete UI coverage.

## Fallback and review

Every real locale falls back to English for a missing message. English must
contain every canonical catalog key. Translation support and linguistic
review are separate: non-English initial text is an AI/machine-drafted,
unreviewed contribution. Automated validation checks technical structure,
not idiomatic quality. Do not change `review_status` to human-reviewed without
actual human review.

## Pseudo and RTL test modes

Debug builds expose `qps-ploc` and `qps-rtl` in the language selector. Pseudo
text accents and expands English messages to find clipping and hardcoded
strings. RTL mode wraps test strings in RTL isolates with Arabic-script test
text. It is not Arabic support and does not make timeline semantics right to
left. Release builds omit both modes from the ordinary selector.
