## Checkpoint 2 — Implementation and findings

### Watch runtime and ARMAGEDDON

The compatibility work already present at recovery is retained. The 14 stack operations, deterministic renderer-policy `Random`/`RandomInteger`, ordered bounded `StreamSet`, Strict/Permissive policies, structured family-deduped warnings, analyzer status, and Sono-GCC exclusion/fallback remain documented as renderer approximations. Exact Sonolus-client behavior is not asserted.

The slow ARMAGEDDON parity test had been doing two complete Watch traversals to compare pixel backends. It now builds the expensive Watch snapshot once and rasterizes that snapshot on CPU and WGPU. Profiling found a second, production-side cost: `WatchVm::new` rescanned the immutable Watch graph to calculate its temporary-memory stack floor for every callback VM. The runtime now computes that graph property once per `WatchRuntime` and supplies the cached floor to callback VMs. A unit test verifies the cached result equals the original graph analysis.

Measured evidence from the inherited profiling work:

- Before caching, a 96-entity sample took 17.10 s for frame 0; VM construction alone was 16.69 s. The full fixture made no first-frame progress within the earlier multi-minute attempt.
- After caching, the 64-entity sample's frame 0 took 0.171 s; callback VM construction was 0.000595 s. This is diagnostic timing, not a broad renderer speedup claim.
- The full 2,231-entity ARMAGEDDON frame 0 took 17.517 s after the change. The measured callback execution was 15.208 s, preprocessing 15.584 s, and callback VM construction 86.9 ms. Remaining cost is real engine evaluation, not repeated graph analysis.
- The bounded full-fixture CPU/WGPU parity test completed in 40.13 s and also passed in the serial attempt before its later timeout and in the parallel suite.

### Gameplay HUD

The HUD is the renderer-owned compositor in `src/render_ui.rs`, distinct from engine-authored Sonolus `Draw` commands and Presentation Studio UI. Watch execution remains the one authoritative gameplay traversal. The HUD consumes the resulting frame state and its explicit external event adapter; it does not infer player judgements from note graphics.

The GUI now exposes load/replace/remove controls for an event-track JSON file, reports loaded event/scoring counts, and explains that Watch rendering does not calculate interactive Play judgements. It loads into a candidate profile so a failed selection does not replace the active profile. Existing profile bindings may also read Watch memory. With no corresponding event or binding, event-backed values remain unavailable/neutral instead of being invented.

The HUD regression was extended to initialize a WGPU-capable session, prepare the real Watch frame once, and render that exact snapshot through both backends. It asserts event-derived gameplay values and time, CPU/WGPU gameplay-state agreement, CPU/WGPU RGB tolerance, visible HUD-on pixels versus the HUD-off compositor on both backends, and byte-identical repeated output per backend.

### Real exported output

The source build discovered FFmpeg/FFprobe from the repository's parent `addons` directory. A real 3-second, 12 FPS, 640x360 MP4 was exported with the Next RUSH Larp 64x fixture, the default renderer HUD profile, and `ui-profiles/example-events.json` using:

`target/debug/renderer.exe render-config target/hud-export-config.json`

The CLI reported 36 deterministic frames and 12.793 s total execution. FFprobe reported H.264 video, 640x360, 12/1 FPS, 3.000 s, 300,668 bytes. The test config disabled BGM/SFX, so this verification output contains no audio stream.

A frame was extracted at 1.2 s to `target/hud-export-frame.png` and visually inspected. It shows the gameplay scene with score `00000100`, life `880`, combo `1`, and `PERFECT`. The final frame follows `render_prepared_frame`, the same compositor path used by preview and export. Thus exported HUD pixels are verified in actual MP4 output; this was not a packaged installer run.

The export succeeded, but this sandbox denied writes to `%LOCALAPPDATA%\Sono-Renderer\performance`; performance-history and diagnostic persistence emitted warnings, and the native notification service also reported an error. These side effects did not fail video export. Do not treat them as a successful persistence/notification validation.
