# Presentation Studio

Presentation Studio is the renderer's standalone composition editor. An ordinary project can import and edit local video and audio without EngineData, LevelData, Chart Studio, WatchVm, Sono-GCC, or Sonolus resources. A pre-rendered Sonolus MP4 is ordinary video media; live Watch-backed sources are not currently a composition source type. See [Subtitles and captions](PRESENTATION_STUDIO_SUBTITLES.md) for local transcription, timed-text import/export, and caption editing. The separate in-game Gameplay UI asset-pack import workflow is documented in [Presentation Studio assets](PRESENTATION_STUDIO_ASSETS.md).

## Project and media model

A `.sonocomp` document uses schema version 21. It stores composition settings, stable composition identity, canonical media-source references (including live child-composition references), ordered tracks, clips, transforms, an ordered typed visual-effect stack, per-clip masks, first-class transitions, source-time mapping, text, keyframes, marker positions, linked A/V identity, user group identity, track locks, generated/still-source metadata, optional preview-only proxy references with probed metadata, an optional export In/Out range, project-local title presets, a project-local H.264/AAC export-quality preset, filled rectangle/ellipse/line generated sources, transition easing, source-free adjustment clips, effect-parameter keyframes, audio-track gain, and optional provenance on ordinary text clips that were imported or created from timed subtitles. The text and timing remain in the existing clip fields. Schema versions 1 through 20 are migrated on load; missing group and text-box fields default to ungrouped clips and no text box, preserving existing presentation. Version 6 migrates without altering existing effect stacks; schema 7 adds the gamma effect variant, schema 8 adds user groups, schema 9 adds optional text backgrounds, schema 10 adds export range, schema 11 adds local title presets, schema 12 adds composition identity/nested references, schema 13 adds export quality, schema 14 adds generated shape geometry, schema 15 adds transition easing, schema 16 adds the opt-in preview proxy reference, schema 17 records source/proxy file signatures and probed dimensions, duration, and codec, schema 18 adds adjustment layers, schema 19 adds animatable effect parameters, schema 20 adds audio-track gain defaulting to unity, and schema 21 adds caption provenance plus a built-in short-form text preset while preserving existing project presets. A path-only proxy from schema 16 is retained for inspection but is considered unverified and is not selected automatically. Unknown fields are preserved, and unknown future schema versions are rejected without rewriting the source file. Media bytes are not embedded.

Tracks have stable IDs, names, kind, ordering, and enabled state. Audio tracks also have mute, solo, and constant linear gain (0–16×); track gain multiplies each routed clip's own animated gain before the shared mix. Video, text, and adjustment layers are composited in track order and clip z-order. Each media clip references a source ID rather than duplicating media. `duration` is always timeline duration. Forward/reverse clips consume `duration * playback_rate` seconds from the source window; reverse treats `source_start` as the low end and plays from the window's high end. Freeze holds the frame/sample at `source_start` for the timeline duration. Removing a track requires its clips to be moved or removed first. Reordering is within the visual or audio stack.

The media bin is independent of timeline instances. It reports source type, stream presence, dimensions, duration, and timeline-use count; search matches display name and path. Video thumbnails decode asynchronously in a single bounded worker, are cached to 64 GUI textures, and are keyed by source ID, path, size, and modification time so relinks/file changes cannot reuse stale images. Remove unused deletes only unreferenced source records from the project and never deletes media files. PNG/JPEG still images have no source duration; each clip instance supplies its duration. Generated RGB solids and filled rectangle/ellipse/line graphics use the same source/clip model without a backing file; generated shapes retain normal clip transforms, opacity, ordering, and animation. A source can have multiple clips; relinking a missing source or replacing an online source probes and validates the candidate before changing its path, keeping every clip reference attached to the same source ID. Missing sources remain visible in the inspector. Dropped audio/video/image files are stream-probed into the media bin, while dropped `.sonocomp` files are schema/cycle validated as nested sources. Each media-bin entry also has a drag handle: dropping audio onto an audio track inserts an audio clip; dropping video or a still onto a visual track inserts a video clip; dropping A/V media onto a visual track inserts a linked audio/video pair. The drop uses the pointer's timeline time and the normal track-lock/stream checks. A `.sonocomp` can also be added through the file picker. Child paths are project-relative when possible, missing children stay inspectable, and relinking selects another `.sonocomp`. Child contents are loaded at render time, so saved child edits propagate without flattening the parent project.

Video containers with both streams can be inserted as synchronized video/audio clips that share one media source and a link-group ID. Moving, trimming, splitting, slipping, deleting, and ripple operations keep linked segments aligned. Explicit unlinking allows independent editing. Source Monitor preview renders a selected visual source through the production FFmpeg compositor in an isolated one-frame composition; its source time, In, and Out are separate from the Program monitor playhead. In/Out ranges can be placed, appended, inserted as a sequence ripple across tracks, or overwritten on the first unlocked compatible track. Overwrite preserves non-overlapping tails and refuses to overwrite a linked pair until it is unlinked.

Nested compositions are live project sources with stable IDs and a 16-level recursion bound. Loading/saving checks existing child references for cycles; rendering repeats the cycle check and reports missing child files. Each child is evaluated from its current `.sonocomp` state and placed through the normal parent clip transform/effect path. To fit the existing separate preview-video and preview-audio FFmpeg workers, the child render is staged inside the job's temporary workspace as full-resolution FFV1 video with PCM audio; this is lossless scratch media, not a persisted/rendered MP4 substitute. Playback shares one temporary workspace for both decoders. Export uses the same path, and the scratch files are removed with the workspace. A parent clip's timeline duration is captured when inserted; shortening the child below a used source window fails validation rather than silently substituting frames.

When media or a font is beside the project, save stores a portable relative path. If a relative path cannot represent it (for example, a different Windows volume), save stores an absolute path. Relative paths resolve from the project directory. The project opens even when referenced files are missing; preview/export reports the missing reference instead of substituting another file.

Video proxies are generated asynchronously through the existing cancellable media-job worker. The current generator writes video-only H.264 MP4 at a maximum 960-pixel long edge; playback audio continues to use the original source. A proxy record belongs to one stable media-source ID and stores lightweight size/modified-time signatures for both files plus probed dimensions, duration, and codec. If either file changes, the proxy is stale and preview falls back to the original. If the original is offline but the proxy signature still matches, preview can use the proxy while export correctly reports the missing original. A valid proxy is normalized to the original source dimensions before the usual clip crop/transform graph, preserving existing source-coordinate and keyframe semantics. **Use valid proxies for preview** is an explicit project preference. Final MP4 export always selects original paths regardless of that preference. Removing a renderer-generated proxy deletes it only if its bytes still match the recorded signature; manually attached proxy paths are detached without deleting user files. These signatures are a fast invalidation check, not a cryptographic content hash.

## Timeline editing

The timeline has a horizontal time ruler, scrollable track rows, zoom, adjustable track height, a snapping toggle, playhead, clip blocks, audio peak summaries, keyframe markers, and timeline markers. The model stores time values; with snapping enabled, dragging snaps to frame boundaries, the playhead, and nearby clip edges; disabling it allows free-time edits. Ctrl/Command-click selects multiple clips. Group/ungroup operates on user groups independently from linked A/V; grouping includes linked partners, and moving or deleting a grouped member acts on the complete group. Duplicates are independent. Drag clips to move or trim either edge. Dropping on another compatible row changes track placement; media-bin drag handles place new clips at the drop time and create linked pairs for A/V sources dropped onto a visual track. Ordinary trim/delete is non-ripple. The explicit Ripple delete operation cuts the selected interval on its track, trims any other clips crossing that interval, removes markers inside the interval, closes the gap on that track, and moves linked partners with their video/audio segments; other unrelated tracks remain in place. Insert-and-ripple shifts all tracks and markers and splits clips crossing the insertion point. Overwrite affects one compatible unlocked destination track. Slip buttons shift the source window by one frame while keeping clip position/duration fixed. Track locks disable inspector editing and reject timeline/model edits. Copy/paste creates another source-linked clip instance, not a linked A/V pair.

Track controls add visual/audio tracks, toggle visibility or audio mute/solo, adjust audio-track gain, change track order, and remove empty tracks. Clip properties include timeline start, source in, duration, video transforms/crop/blur/opacity, text, and audio routing/gain/pan/fades. Audio source peak summaries are bounded to 512 bins and reused by the media bin and timeline.

Undo/redo stores up to 40 composition snapshots. It covers edits made through the timeline/inspector, track controls, media insertion/relink, and voiceover insertion. Undoing an audio clip insertion retains its media source and WAV file in the media bin.

## Animation and text

Scalar keyframes are stored by stable property identity. Current animated properties are:

- Video: X, Y, Scale X/Y, rotation, opacity, crop edges, and Gaussian blur.
- Audio: gain and pan.
- Text: X, Y, font size, and opacity.
- Adjustment: blend opacity.

Visual effects use an ordered `VisualEffectInstance` vector on video and adjustment clips. Each item has a stable ID, enabled/bypass flag, typed parameters, and an explicit place in the vector. The production compositor applies enabled items sequentially in that order for both preview and export. Implemented filters are Gaussian blur, brightness, contrast, saturation, hue, sharpen, gamma (0.1–10), and chroma key (video clips only). Brightness, contrast, saturation, gamma, and hue values can be keyed with the existing scalar-keyframe easing model; FFmpeg evaluates the expressions at frame timestamps. The effect inspector lists each key so its time, value, and outgoing easing can be edited, and provides jump/remove actions; effect keys also appear on the clip's timeline row. Gaussian blur, sharpen, and chroma-key parameters remain static. Adjustment clips have a timeline span and apply their stack to the already-composited image beneath them; their opacity animates the blend between the unmodified and adjusted result. They have no media source, transform, mask, or audio routing. Legacy clip blur remains a pre-stack property so old project values and blur keyframes preserve their exact meaning. Chroma key is a baseline FFmpeg keyer, not a professional spill-suppression system.

The editor marks animated properties, draws keyframe markers in the timeline, and lets a user set a value at the playhead, add/edit/remove keys, choose easing, and jump to a key. The selected property also has a baseline graph view: click to select a key, Ctrl/Command-click to multi-select, drag selected keys together without crossing unselected neighbors, and copy/paste a key group relative to the playhead. Evaluation holds the first value before the first key and the last value after the final key. Duplicate-time keys are rejected. Easing is linear, hold, ease-in, ease-out, or ease-in-out; cubic Bezier handles are not available. Animated crop and blur are scheduled at composition frame times in the FFmpeg graph; unusually long animated spans above the bounded command schedule fail with a clear error.

Video clips may have a rectangle or ellipse mask. Bounds are normalized against the cropped/scaled clip image before rotation and positioning. Feather is a fraction of the image's short edge, and invert selects the outside region. Mask X/Y/width/height/feather use the same scalar keyframes and interpolation as transforms. The mask is evaluated in the production compositor after the ordered effect stack and before clip opacity, then transformed and overlaid. Freeform/Bezier masks are not supported.

Transitions are separate serialized objects linking two overlapping visual clips on the same track. The incoming clip must be above the outgoing clip. A dissolve fades the incoming clip over the outgoing image; dip-to-black and dip-to-white place a full-frame color overlay over the transition interval. Each transition can use Linear, Hold, Ease in, Ease out, or Ease in/out progression. New transitions are centered in the shared overlap, and duration changes preserve the interval center. The timeline draws a colored band and the clip inspector can add, edit, change type/easing, and remove transitions. Moving a participating clip repositions the transition within the remaining overlap or rejects the move if its duration no longer fits. Splitting through the transition interval is rejected; remove or reposition the transition first. Removing a clip also removes transitions that reference it.

Constant source-time mapping supports forward 0.1x–8x, reverse, and freeze. The clip keeps its timeline duration; its source window bounds are checked against the referenced media. Preview and MP4 export use the same filter graph. Audio follows the same speed and direction: FFmpeg `atempo` changes both duration and pitch, reverse audio is reversed, and audio paired with a frozen video is silence. There is no pitch-preserving time stretch or variable-speed ramp editor. Reverse uses FFmpeg's buffering reverse filter, so long clips may require substantial temporary memory.

Text is an ordinary composition clip. It supports content, position, animated font size/opacity, fill, outline, shadow, left/center/right alignment, an optional padded background box with color/opacity, and a selected TTF/OTF/TTC font. Three project-local built-in presets (centered title, lower third, subtitle banner) create ordinary editable text clips. A selected text clip's style can be saved as a project-local preset, reused at normalized positions with typography/padding scaled by composition width, and removed if it is a custom preset. Font paths follow the same relative/absolute project rules. If no font is selected, the platform's supported default font is used.

## Portable composition templates

Presentation Studio can save the current edit as a portable `.sonotemplate` (schema 1) and apply it to an open composition. This is data for the existing NLE, not a second timeline/compositor: tracks, clips, ordered effects, masks, keyframes, audio properties, transitions, groups, links, and markers are copied as normal editable objects. Applying is one undoable project edit. Save/reopen and final export continue through `.sonocomp` and the production composition pipeline.

Every referenced imported source becomes a required media slot with stream/image requirements and descriptive dimensions; media bytes and paths are not embedded. The user must bind each slot to a source already present in the target media bin. A slot cannot silently pick an unrelated source. Path-free solid and shape sources are included as procedural assets. Nested-composition file paths and machine-specific custom-font paths are rejected when capturing a portable template; use ordinary media slots or install/select a shared system font instead. Template load is bounded to 16 MiB, schema-versioned, validates the NLE object graph through the production project validator, and saves via a flushed same-directory staging file and atomic replacement. Unknown template fields are retained.

Text clips may expose simple string parameters using `{{param:name|default text}}`. Applying a template replaces those tokens in ordinary text clips; it does not retain a runtime template binding. Other styling remains editable on the resulting clips. The GUI offers Save Template / Apply Template, source-slot selection, parameter fields, and a responsive-layout toggle. The low-level `CompositionTemplate` API is also available for workflow automation.

Responsive placement scales X and Y positions by their canvas ratios and scales visual/text sizes uniformly by the smaller canvas ratio. A detected full-canvas, unmasked, uncropped video layer is instead centered and scaled to cover a changed aspect ratio; this is useful for blurred backgrounds. This is a practical reflow rule, not a constraint solver or a breakpoint-based layout system. Inset positions and sizes may still need adjustment for a very different aspect ratio. Preview and export still evaluate the same copied clip properties in the existing compositor.

The portable template workflow is covered by `composition::tests::portable_template_*`. The opt-in real-media acceptance test `composition::tests::real_ffmpeg_template_reuse_across_ordinary_sources_portrait_and_gameplay` exercises one template with two unrelated local MP4 inputs, a landscape and portrait composition, a generated graphic, mask, ordered effects, animated outlined/background text, transition, manual post-apply edits, save/reopen, and H.264 export. It also applies those same NLE objects to a pre-rendered Larp gameplay MP4 as ordinary media; this does **not** open Watch or constitute a live gameplay-source adapter. The test writes preview PNGs and validated MP4s under `artifacts/presentation-template-validation/`.

Composition coordinates are pixels from the top-left of the output canvas. New video clips are initially fit inside the canvas. The source is not automatically reflowed when a user changes composition dimensions later; positions and scales remain explicit project values.

## Playback, preview, and audio

Play/Pause/Stop, seek, scrub, and frame-step controls use the same composition filter graph as export. FFmpeg decodes video frames and mixes the timeline audio; CPAL sends the mix to the system's default output device. The audio output callback's submitted sample frames are the playback clock. Video preview is reduced to a maximum 960-pixel edge and consumes frames against that clock; if decoding cannot keep up, the preview holds/drops frames rather than slowing timeline time. Audio underflow count and playback errors are surfaced in the UI.

Seeking stops the current decode pipes and starts them at the new timeline position. This is correct but can take time on long or complex compositions because preview decode is a bounded streaming path, not a cached nonlinear random-access decoder. Scrubbing is therefore seek-preview oriented rather than a high-speed jog/shuttle. The still-frame **Render Preview** control remains available at full composition resolution.

Ordinary imported audio, audio from explicitly enabled video clips, and recorded WAV clips use the same audio filter graph for playback and export. Overlapping clips are mixed; track and clip mute/solo, track gain, animated clip gain, fades, and pan are applied there. The audio inspector offers a crossfade action for eligible same-track overlaps; it sets the existing outgoing fade-out and incoming fade-in envelopes to the shared overlap duration. During playback the CPAL output callback publishes lock-free recent RMS/peak values and a near-full-scale clipping flag for the master meter. This meter describes samples sent to the output callback; it is not a hardware loopback meter. Playback needs an available default output device. Microphone capture remains explicit; Record Voiceover can start timeline playback and then capture a take at the playhead. The input meter and capture backend remain separate from playback output. Physical-device A/V latency and long-run drift have not been measured in this environment.

## Save, autosave, and recovery

Explicit Save atomically replaces the versioned `.sonocomp` file. After edits, the application writes an atomic, versioned recovery checkpoint after 20 seconds, including while the user is on another workspace tab. Checkpointing waits while voice capture or composition export is active. A dirty composition also prompts on application close with choices to save the project, save a recovery checkpoint, discard changes, or keep editing. Checkpoints live separately under the application state directory, keep absolute local media/font references, do not replace the explicit save, and are capped at the 20 most recently modified snapshots. On opening the editor, available checkpoints are listed with explicit Recover and Remove actions. Recovering restores an editable working copy; Save is still required to update the project file. Corrupt/unsupported checkpoints are ignored rather than blocking application startup.

Recovery is project metadata, not an archive of media files. An abrupt process or power failure can still lose edits made since the last checkpoint. Recorded partial WAV recovery is handled by the microphone staging path.

## Export

Export and preview share the authoritative composition model and FFmpeg filter graph. A valid displayed preview frame can be saved separately as PNG through a same-directory staged write; edits invalidate the saved-frame candidate so stale pixels cannot be mislabeled as the current project. MP4 output uses H.264 and AAC when audio is routed. The project-local quality choices are Draft (CRF 26, veryfast, AAC 128 kbps), Balanced (CRF 18, medium, AAC 192 kbps), and High quality (CRF 16, slow, AAC 256 kbps). Balanced matches the historical encoder arguments and is the migration/default choice. These are software H.264 presets; hardware encoder selection is not exposed. The optional In/Out range is persisted in composition time, trims both final video and mixed audio, and changes the expected output duration; playback and preview continue to show the full timeline. Export writes to a staging path, checks the container and streams with FFprobe, then publishes the final output. Existing output is not silently overwritten. Export supports cancellation and reports FFmpeg errors. Preview/export have different resolution and performance paths but use the same clip ordering, transforms, keyframes, and audio routing.

## Keyboard shortcuts

Shortcuts are disabled while an egui text field wants keyboard input:

- Space: play/pause
- Left/Right: previous/next frame
- Delete: delete selected clip
- S: split at playhead
- Ctrl+C / Ctrl+V: copy/paste selected clip
- Ctrl+D: duplicate selected clip
- Ctrl+Z: undo
- Ctrl+Y or Ctrl+Shift+Z: redo

## Validation

The model tests cover track assignment/order/locks, linked A/V split/move/slip/unlink/delete, source-range insertion, append/insert/overwrite/ripple behavior, marker movement, effect validation/order/bypass/schema migration, mask geometry/invert/feather/keyframes, transition overlap/persistence/compositor construction, constant source-time mapping/audio tempo, keyframe boundaries/easing, serialization/migration, relative media/font paths, unknown-field preservation, recovery serialization, snapping, audio mixing, and frame selection. The opt-in real FFmpeg integration test imports ordinary MP4/WAV inputs, a video+audio MP4, PNG and JPEG stills, and generated color/shape sources; it saves/reopens, verifies linked IDs and still metadata, renders Program and Source monitor frames, streams preview video/PCM, exports landscape and vertical MP4s, and validates the outputs with FFprobe. It applies ordered color effects, chroma key, all mask shapes/states, animated mask movement, eased and linear transition frames, both dip types, forward/reverse/freeze source-time mapping, title presets, nested edits, and a retimed MP4 export to actual media. The vertical export uses the High quality H.264/AAC preset and is FFprobe validated. A separate real FFmpeg pipe test checks that text and animated-filter command files remain available for continuous playback.

The continuation also tests effect-parameter keyframe validation, transactional time/value/easing edits, duplicate-time rejection, interpolation/filter construction, locked-track rejection, and save/reopen; schema 19→20 migration preserves effect keys and defaults audio-track gain to unity. The real FFmpeg fixture renders animated brightness at two timestamps, compares the later preview pixel against a decoded MP4 frame, checks that a 0.5× audio-track gain halves decoded float-PCM RMS, and compares a dissolve between source-trimmed 0.5×/0.75× clips in preview and MP4 export. The track-drop helper test verifies stream/track compatibility, exact destination track placement, linked A/V identity, and transactional rejection. The composition edit-history test exercises insertion, grouped editing, undo/redo, media-bin source retention, and save/reopen against one authoritative project model. These tests exercise production model/filter paths; egui drag gestures and the full desktop editing workflow were build-checked but not interactively exercised in this environment.

Run the focused model tests:

```powershell
cargo test --locked --lib composition::tests
cargo test --locked --lib timeline_playback::tests
```

Run the real-media integration fixtures when the app-managed FFmpeg/FFprobe pair is already present:

```powershell
cargo test --locked --lib composition::tests::real_ffmpeg_standalone_video_audio_project_preview_and_mp4_export -- --ignored --nocapture
cargo test --locked --lib composition::tests::real_ffmpeg_template_reuse_across_ordinary_sources_portrait_and_gameplay -- --ignored --nocapture
cargo test --locked --lib timeline_playback::tests::video_pipe_keeps_animation_and_text_filter_files_alive_until_decode_finishes -- --ignored --nocapture
```

The first command writes representative PNGs to [`artifacts/nle-validation`](../artifacts/nle-validation/README.md), including the adjustment-layer before/active pair described in [adjustment-layer-validation.md](../artifacts/nle-validation/adjustment-layer-validation.md). They are synthetic production-compositor fixtures, not a finished visual theme. The current Windows environment build-checks the GUI, but this pass did not interactively exercise mouse/keyboard editing, open a physical CPAL output device, or test voiceover recording from the packaged application. The master meter's lock-free level calculation is unit-tested; actual hardware output levels remain unverified. Live gameplay remains deferred.
